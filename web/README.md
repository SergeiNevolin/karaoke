# Караоке — веб-интерфейс (React + TypeScript)

Минималистичный интерфейс, в котором можно петь:
каталог песен → минус + бегущая строка с подсветкой слов →
микрофон с live-уровнем и полосой тона → оценка 0–100.
Песни загружаются прямо через интерфейс (кнопка «Загрузить»).

```powershell
cd web
npm install
npm run dev      # фронт
npm test         # 38 тестов: логика + аудио-движок на моках
npm run build    # прод-сборка
```

Стек (актуальные версии): React 19, Vite 8, Tailwind CSS 4,
framer-motion 13, lucide-react 1.x, zustand 5, pitchy 4
(детект тона микрофона, McLeod Pitch Method).
Бэкенд: FastAPI — принимает загрузки и гоняет GPU-пайплайн в фоне.

## Запуск (полный режим: фронт + загрузка песен)

```powershell
# терминал 1 — бэкенд (GPU-пайплайн + каталог)
python -m uvicorn karaoke_api.app:app --port 8000

# терминал 2 — фронт
cd web
npm install
npm run dev      # http://localhost:5173
```

Кнопка «Загрузить» в каталоге видна, когда бэкенд доступен.
Принимаются аудио (mp3/wav/flac/m4a/ogg) и клипы (mp4/mov/mkv/webm —
аудиодорожка извлекается автоматически).
Процесс: выбор файла → параметры → прогресс по стадиям
(вокал → текст → тон → файлы) → песня открывается сама.
Можно приложить правильный текст: вставьте ссылку Genius (подтянется
автоматически) или вставьте текст построчно — он нечётко наложится на
тайминги Whisper вместо распознанного. Без бэкенда интерфейс работает
в режиме чтения статического каталога.

Микрофон требует безопасный контекст: `localhost` подходит,
для доступа по сети — только через `https`.

## Только фронт / prod-режим

```powershell
cd web
npm run build    # dist/ подхватится бэкендом: http://localhost:8000/
```

## Откуда берутся песни

```powershell
# 1. собрать песню GPU-пайплайном (Demucs + Whisper + pitch)
python src/make_karaoke.py "music/трек.mp3" --model htdemucs --whisper large-v3 --lang ru

# 2. экспортировать в веб-каталог (минус жмётся в mp3 через ffmpeg)
python web/scripts/export_songs.py
```

Экспорт кладёт в `web/public/songs/`:
`<id>/minus.mp3`, `<id>/lyrics.json`, `<id>/pitch.json` + `manifest.json`.

## Редактор тайминга (кнопка-карандаш в плеере)

Слушаем оригинал вокала (не минус) и расставляем слова точно:
- транспорт: play/пауза, «строку с начала», зацикливание строки,
  скорость 0.5/0.75/1× (тон сохраняется), громкость;
- обзор-трека: волны вокала + регионы строк, клик — перемотка;
- детальный таймлайн строки: слова таскаются за края прямо по волне,
  клик — послушать место, даблклик — слово целиком, масштаб ±;
- таппинг: играет строка, жмёте ТАП (или пробел) в ритме слов,
  последний тап закрывает строку;
- точная подгонка: кнопки ±50мс и стрелки клавиатуры
  (←/→ — начало, Shift — ×4, Alt — конец);
- чипы слов с таймингами, список строк (клик — выбрать и слушать),
  импорт текста/Genius, сохранение в браузер + скачивание .json.

Требует `vocals.mp3` + `waveform.json` в песне — их кладёт
`python web/scripts/export_songs.py`. При совпадении числа слов
точные word-timings сохраняются, иначе слова раскладываются равномерно.

## Как устроено пение

- `src/components/Player.tsx` — плеер: `<audio>` с минусом,
  rAF-цикл синхронизирует текст (`locate()` по word-timestamps),
  текущая строка подсвечивает спетые слова янтарным,
  прыгающий шарик летит от слова к слову и приземляется ровно в начало каждого.
- Микрофон: `getUserMedia` → `AnalyserNode` (уровень) +
  `pitchy` каждые ~120 мс (нота). Нота сравнивается с эталоном
  `pitch.json` по pitch-class (октава игнорируется, допуск ±1 полутон).
- `PitchStrip` — canvas: серая россыпь = эталон, жёлтые точки = попал,
  розовые = мимо.
- В конце `buildScore()` считает оценку, как в `src/pitch.py`.
